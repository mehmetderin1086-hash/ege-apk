# Asistan — ajan çalışma kuralları

Türkçe sesli/yazılı iPhone asistanı (SwiftUI, Swift 6, iOS 27, XcodeGen). Bu dosya Antigravity, Codex ve Claude Code için ortak kılavuzdur.

## Komutlar (hepsi repo kökünden)
- Proje dosyası üret (YENİ .swift DOSYA EKLEDİKTEN SONRA ŞART): `~/Developer/.tools/xcodegen/xcodegen/bin/xcodegen generate`
- Derle (simülatör): `xcodebuild build -project Asistan.xcodeproj -scheme Asistan -destination 'platform=iOS Simulator,id=B3D3ABF3-2FE1-4EEA-8896-8386034F6802' 2>&1 | grep -E "error:|BUILD"`
- Birim testleri (~30 sn, 350+ test): aynı komutun `test … -skip-testing:AsistanUITests` hâli; sonuçta `Test run with N tests … passed` satırını kontrol et.
- Arayüz testleri (~10 dk): `-only-testing:AsistanUITests`; tek test: `-only-testing:AsistanUITests/KisisellestirmeUITestleri/testAd`.
- Test planları: `araclar/test.sh duman` (hermetik, ~2 dk, sahte model: çekirdek birim testleri + SahteModelUITestleri + çekmece), `araclar/test.sh tam` (birim + bütün hermetik UI testleri; canlılar atlanır), `araclar/test.sh canli` (gerçek model/ağ, ücretli, ASISTAN_CANLI=1). Ek bağımsız değişkenler xcodebuild'e geçer; günlük `~/Developer/.build/asistan-test-<kip>.log`; simülatör `ASISTAN_SIM_UDID` ile değiştirilebilir. Planlar `Planlar/*.xctestplan` (şemada varsayılan Tam); plan kullanılınca ortam değişkenleri planın `environmentVariableEntries` alanından gelir. Yeni UI testi `XCUIApplication.hermetik(senaryo:)` ile başlar (`--sohbet --sahte-model --animasyonsuz` ve ASISTAN_TEST=1; dikkat: OnayKapisi testte true olur, onay diyaloğu sınayan test bunu kullanmaz). Gerçek ağa/modele çıkan test `try canliKapisi()` ile başlar. `Thread.sleep` yerine `bekle(_:_:)` / `kosulBekle(timeout:aralik:_:)` kullan. İstisna: OtomasyonKurulumUITestleri (fiziksel cihazda Kestirmeler/Mail akışı, sabit beklemeler bilinçli).
- Telefona kur (iPhone "Mehmet iPhone'u", UDID 00008120-001C592421D8A01E): `./telefona-kur.sh` (varsayılan Release; `--sinama` Debug kurar ve `--asistan-*` sınama bayrakları yalnız onda vardır; `--bekle[=sn]` kilidi bekler, varsayılan 600 sn; kilit doluysa 75 ile çıkar). Ayrı derivedData kullanır, simülatör testleriyle aynı anda çalışabilir. Betik `~/Developer/.build/asistan-telefon-<UDID>.kilit` kilidini alır, CFBundleVersion'ı YYYYMMDDHHMM verir, git hash'i ve değişmiş dosya sayısını Info.plist'e yazar (`araclar/surum-damgala.sh`), tam günlüğü `~/Developer/.build/asistan-kur-son.log`'a yazar, `~/Developer/.build/asistan-kurulumlar.log`'a satır ekler, dSYM'leri `~/Developer/.build/asistan-dsym/`'de saklar (son 5). Telefonda cihaz testi koşacaksan önce `source araclar/kurulum-ortak.sh; kilit_al <UDID>` (ardından üst düzeyde `trap kilit_birak EXIT`) ya da kilit dolu mu diye bak. Kabuk testi: `zsh araclar/testler/kurulum-ortak-test.sh`.
- Cihaz kabul turu: `araclar/cihaz-kabul.sh [--kurma] [--yalniz hiz-kabul,ofis-sinama,…] [--bekle[=sn]] [--udid X] [--liste]`. Telefon kilidini bütün tur boyunca tutar (`kilit_al`; `--bekle` verilmezse kilit doluysa hemen 75, verilince `sn` yoksa 600 sn bekler; `--kurma` kurulum defterindeki son kurulum Release ise 64 ile çıkar, çünkü sınama bayrakları yalnız Debug'da vardır; çocuk `./telefona-kur.sh --sinama` ASISTAN_KILIT_SAHIBI ile yeniden girer). Debug kurar, sınamaları sırayla `devicectl … process launch --terminate-existing com.mehmetderin.asistan -- --asistan-<ad> --sinama-kosu=<uuid>` ile koşturur. Documents/asistan-<ad>.json `kosu` = uuid ve `kosuBitti` = true olana kadar 5 sn arayla çekilir; olmazsa `{kabulZamanAsimi:true}` işareti yazılır. Sonuçlar `~/Developer/.build/asistan-kabul/<YYYYMMDD-HHMMSS>/` altına çekilir (son 10 tur kalır), tur sonunda uygulama olağan açılışa döner. Önceki turla `araclar/kabul_karsilastir.py` karşılaştırır (`karsilastirma.txt`); iç içe `…[].bitti` false ya da `…[].hata` dolu da başarısızdır. Kurallar: süre alanı (`…Sn`, `…Ms`, `sureSaniye`) %20 ve 0,2 sn / 200 ms'den çok artarsa gerileme; boolean true→false gerileme; `tamamlandi` false, `asama` ≠ tamamlandi, `hata` dolu ya da `zamanAsimi` true ise başarısız. Kurulum defterine `kabul_<gecti|gerileme|altyapi|kurulum_hatasi>` satırı yazılır. Çıkış kodları: 0 = geçti, 1 = %20'den kötü gerileme ya da başarısız sınama, 2 = altyapı hatası (telefon kilitli, açılamadı, dosya çekilemedi, kurulum hatası), 64 = kullanım hatası (ya da `--kurma` ile Release kurulu), 75 = kurulum kilidi dolu. Sınama raporları `AsistanSinama.kaydet(dosyaAdi, sonuc, bitti:)` ile yazılır: `kosu`, `surum` ve `kosuBitti` alanlarını ekler; ara yazım `bitti: false`; son yazım başarıdan bağımsız SinamaKaydi satırı düşer. Yeni sınama da bu yazıcıyı kullanır ve cihaz-kabul.sh `SINAMA_TABLOSU`'na eklenir. Testler: `/usr/bin/python3 -I araclar/testler/test_kabul_karsilastir.py`, `zsh araclar/testler/cihaz-kabul-test.sh` (sahte devicectl; ortam değişkenleri ASISTAN_DEVICECTL, ASISTAN_KABUL_DIZINI, ASISTAN_KABUL_ARALIK, ASISTAN_KABUL_ENCOK).
- TestFlight (yalnız iç test): `araclar/testflight-yukle.sh [--kuru] [--kirli-tamam] [--bekle[=sn]] [--sakla]`. Ayrı arşiv kilidi (`~/Developer/.build/asistan-telefon-arsiv.kilit`, telefon kilidiyle çakışmaz), YYYYMMDDHHMM derleme numarası, Release arşiv (derivedData `~/Developer/.build/asistan-dd-arsiv`, arşiv `~/Developer/.build/asistan-arsiv/`), `ExportOptions.plist` ile dışa aktarma + yükleme (destination=upload). `--kuru` yalnız arşivler ve .ipa üretir (Keychain okunmaz, yükleme yok). `--sakla` verilmedikçe arşiv ve çıktı yalnız başarılı koşunun sonunda silinir; başarısız koşunun arşivi tanı için kalır (elle sil). Kirli ağaçta `--kirli-tamam` olmadan 3 ile çıkar; diğer kodlar: 2 Keychain'de anahtar yok/bozuk, 4 önkoşul eksik, 64 kullanım hatası, 75 kilit dolu. API anahtarı Keychain'de: servis `asistan-asc-api`, hesap = anahtar kimliği, parola = base64 .p8; issuer servis `asistan-asc-issuer`, hesap `asc`. Anahtar Admin ya da App Manager + bulut dağıtım sertifikası izniyle üretilir. Anahtar yazdırılmaz, diske kalıcı yazılmaz (.p8 geçici 600 dosyada, çıkışta silinir); günlük `~/Developer/.build/asistan-testflight-son.log` (kimlik ve issuer maskeli). Defter sonuçları `testflight_*` (UDID alanı 'testflight'); dSYM `asistan-dsym/<SURUM>-<GIT>-testflight`. Kabloyla kurulum aynı bundle kimliğiyle TestFlight sürümünün üzerine yazar; tur sonrası TestFlight'tan yeniden kur. Kabuk testi: `zsh araclar/testler/testflight-yukle-test.sh`.
- Çökme kaydı: `xcrun devicectl device info files --device <udid> --domain-type systemCrashLogs | grep Asistan`, sonra `device copy from`. Tanı paketi: uygulamada `/tani` ya da Sağlık → Tanı paketi (maskeli .zip: tani.log, tani.1.log, ozet.txt; `TaniPaketi`).

## Swift 6 / eşzamanlılık tuzakları (çökme sınıfı)
- `SWIFT_DEFAULT_ACTOR_ISOLATION = MainActor`. Sistem kuyruğundan çağrılan HER kapanış/delegate `nonisolated` ya da `@Sendable` olmalı: `requestAuthorization`, `installTap`, `BGTaskScheduler.register`, URLSession delegeleri, `MXMetricManagerSubscriber`, `UNUserNotificationCenterDelegate` (tamamlayıcılı varyant), `AVCaptureVideoDataOutputSampleBufferDelegate`, `NSItemProvider` tamamlayıcıları. Aksi hâlde `dispatch_assert_queue` ile çöker; simülatör testleri bunu YAKALAMAZ, telefonda çöker.
- `Shape`/`Equatable` uyumu olan değer türlerini `nonisolated` yap (`@concurrent` bağlamda "main actor-isolated conformance" hatası).
- `BGContinuedProcessingTask`: kayıt olmadan `submit` çağrısı assertion ile çöker → `ArkaPlanSurdurucu.kaydol` görev başına. Motorlu indirme kendi görevini `IndirmeSurdurucu` ile ister (kimlik `ArkaPlanSurdurucu.onek + ".indir-" + yeni UUID`, istek başına; kayıt id'si DEĞİL, çünkü motorluTekrar aynı kayıt id'siyle döner ve aynı kimliği yeniden kaydetmek çöker; strateji `.queue`: sistem hemen veremezse istek kuyruğa girer, o arada ArkaPlanGorevi ~30 sn yedeği sürer; süre dolunca indirme iptal edilmez, parçalar 'Yeniden dene' için korunur).
- Süre sınırı: `sureSinirli` varsayılan olarak bırakılabilir (iptali dinlemeyen iş beklenmez). Ortak WKWebView'u (`TarayiciOturumu.ortak`) kullanan her adım `TarayiciOturumu.ortak.sirayla { … }` içinde koşar (FIFO `SiraKilidi`; 25 sn'yi aşan sahip zorla devralınır, sonucu bayat sayılır). Kullanıcı onayı kilidin dışında beklenir, onaydan sonra sayfa yeniden doğrulanır. `sirayla` iç içe çağrılmaz. `birakilabilir: false` yeni kodda kullanılmaz.
- Bildirim eylemleri (P2.14) `BildirimEylemleri.isle`de; `didReceive` tamamlayıcılı ve nonisolated kalır, tamamlayıcı ancak iş bitince çağrılır (`isle` her dalda bir kez). Ana aktöre yalnız String taşınır. Ertelenen bildirimin kimlik öneki 'ertele.' olur; 'tetik.' önekini TetikDeposu.planla siler. Arka plan yanıt bildirimi istem DEĞİL `sohbetAnahtari` taşır (dokununca soru yeniden sorulmaz). 'Sesli dinle' P2.13 devrini kullanır: `GorevKopru.teslimEt(_, sesli: true)`. LiveActivityIntent perform uygulama sürecinde çalışır, Beyin'e `IsKoprusu.durdurKancasi` ile bağlanır (AsistanApp.init kurar); kanca yoksa ya da iş yoksa açık etkinlikler 'Durduruldu' ile kapatılır.
- MPRemoteCommand addTarget ve AVAudioSession.routeChangeNotification gözlemci kapanışları nonisolated/@Sendable; ana aktöre yalnız Sendable değer (Bool/String/Float) taşıyıp Task { @MainActor in … } ile geç. Ses yolu yenilemesini ölçüm döngüsünün içinden doğrudan await etme (durdur o görevi iptal eder, basla erken döner); ayrı Task aç.
- Python heredoc ile Swift yazarken `\b` kontrol karakterine dönüşür ("Unprintable ASCII"); regex'te `[\s\S]*?` kullan (`.` satır geçmez).
